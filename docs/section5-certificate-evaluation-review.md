## Mathematical and computational contracts

- **CE01 — source reviewed:** the packed vector is exactly `(B*K+J)^depth` applied to `(3139,1313)`. Grouping by the number of outer letters preserves each ordered matrix word. The grouped-coordinate bound is `3139*61^depth`, using the maximum row sum of `K+J`. The packing base `2^(6*(maximum+1)+12)` is strictly larger than every required coefficient at all depths at most `maximum`. Extraction proves an `ofDigits` identity and checks every digit bound; absence of carries is proved rather than presumed. Out-of-range zero counts return zero, consistent with an empty word layer.
- **CE02 — source reviewed:** the inverse packed step uses determinant `306*B^2+180*B+18`, which agrees with `(22B+9)(18B+6)−(18B+12)(5B+3)`. Both natural subtractions are justified by explicit equalities expressing the minuend as the subtrahend plus the positive determinant times the previous coordinate. Thus neither truncated subtraction nor floor division changes the recovered packed value. Correctness is asserted for a genuine recurrence output, not for an arbitrary pair supplied to the inverse function.
- **CE03 — source reviewed:** the packed binomial row is `(B+1)^depth`, and its digits equal binomial coefficients under the proved coefficient bound. The descent divides exactly by `B+1`. The vector and binomial oracles use the same global packing base, matching the streaming invariant's smaller-depth calls.
- **CE04 — source reviewed:** natural-to-integer word, grouped-word, and prefix-sum casts use semiring homomorphisms, including the genuine matrix ring homomorphism. They preserve multiplication order and finite sums. The natural kernels cast to the exact integer numerator matrices, and the vector casts to `(3139,1313)`.
- **CE05 — source reviewed:** packet evaluation applies the repeated tail first to the input vector and then applies its first letter, yielding the stated left-to-right matrix word. The commutator is `KJ−JK = [[−6,−6],[3,6]]`, with the correct sign. The repair is the signed factor `packet.coefficient * 18^packet.layer` times that commutator, tail, and vector in that order. The baseline uses `2K+J = [[53,48],[13,42]]` and the explicit factor 16.
- **CE06 — source reviewed:** the increment vector is exactly `(2K+J−16I)*(55,23) = (3139,1313)`. The final numerator decomposes as `16*(2K+J)^depth*(55,23)` plus the initial ordered mass plus all signed packet masses. `capacityValid` is required before replacing the signed allocation by its natural-valued realization, so negative values are not silently lost by `toNat`. The packet length and capacity requirements are supplied through that existing predicate.
- **CE07 — source reviewed:** the final mass certificate keeps two numerical equalities explicit: the stream must evaluate the actual initial row list to the supplied pair, and the baseline plus that pair plus the actual packet list must equal the stated target. It neither assumes the graph response directly nor validates those large numerical equalities on its own. The audit includes a corollary passing these exact hypotheses through `allocation_massMatrix_eigenvector` to the actual graph's original three-state mass matrix and eigenvector `(55,46,23)`.
- **CE08 — source reviewed:** `fastBinomial` uses binomial symmetry only under `index ≤ top`; outside that range it returns the proved zero value. The auxiliary rank function carries length and zero count, and its correctness theorem explicitly initializes them to the actual word values. It preserves false-before-true ordering and the strict remainder cutoff. The optimized allocation equals the original allocation on every word, and `fastCapacityCheck_iff` proves exact equivalence to the original exceptional packet capacity predicate, including both its lower and upper bounds.
- **CE09 — source reviewed:** the Boolean packet traversal always checks packet length, then accepts either the original slack inequality or a separately sound exceptional check. `allocationPacketsCheck_correct` requires soundness of that exceptional checker for every packet in the supplied list; it does not trust an arbitrary Boolean callback. Its result is exactly the length-and-alternative component needed by `capacityValid`. Other row/slack shapes and support-disjointness conditions remain separate requirements. The ordinary exceptional checker is also proved sound. Short-circuit execution does not drop a mathematical condition.
- **CE10 — source reviewed:** the later `CorrectionPacket.fastZeros` formula counts `2*layer+1` zeroes from the opposite pairs, one zero precisely when the first tail letter is false, and `remaining+1` zeroes precisely when the repeated tail letter is false. `fastZeros_correct` proves this equals the original packet zero count for every packet, including all four first/repeated letter combinations. `allocationPacketsCheckFast_correct` substitutes only this proved-equal slack index; it retains the original length guard and exceptional-check soundness premise. The formula avoids constructing the replicated tail solely to count its zeroes.
- **CE11 — source reviewed:** the four scalar specialization wrappers first invoke the original natural or integer moment theorem with its capacity, moment, binomial-table, and group-check hypotheses. They then rewrite the explicit equalities identifying the allocation, depth, and base. The word list, allocation weights, powers 232 and 70, factors 4 and 5, and denominator-cleared thermal factor `8^(depth+1)` are unchanged. The natural thermal equality retains its existing reversed orientation. These wrappers avoid costly endpoint conversion without proving or presuming any new concrete numerical check.
- **CE12 — source reviewed:** `CompressedAllocation.length_certificate` invokes the previously proved all-zero allocation value and requires both `capacityValid` and the explicit scalar numerical equality. Every correction packet has an opposite pair and therefore contributes zero to the all-false word. The retained row expression includes the strict positive-remainder indicator, covering depth zero as well. The new theorem specializes the existing length formula; it does not itself establish the large numerical identity or actual graph distance.
- **CE13 — source reviewed:** `packedBitDigit` shifts by `bits*zeros` and masks with `2^bits−1`. Core natural-number bitwise lemmas prove equality to division by `(2^bits)^zeros` followed by remainder modulo `2^bits`, for every input and including `bits=0`. The grouped-vector and binomial extractors retain the original `zeros ≤ depth` guard and out-of-range zero result. No carry bound is newly presumed: validity as a grouped coefficient still follows through the previously proved packed-row semantics.
- **CE14 — source reviewed:** the bit stream uses the same inverse packed-vector descent, exact binomial-row division, state advancement, and terminal evaluation as the original stream. Induction proves equality for arbitrary states and packed inputs. The floor evaluator keeps the first-false and first-true coefficients attached to the same ordered kernel actions. The final bit evaluator uses exactly `bits=6*(depth+1)+12`, matching `matrixPackingBase`, and handles depth zero through the same explicit branch. Its unconditional equality to `initialMassEvaluation` preserves the original ordered-mass theorem. A direct audited corollary passes explicit bit-evaluation and final-integer equalities to the actual three-state graph mass conclusion. This is a correctness result; no speed improvement is asserted without measurement.

No mathematical or semantic discrepancy was found in the reviewed implementation. The inspected results do not establish the remaining large numerical identities, the full seed certificates, or physical exponent existence. The proof-producing reduction uses ordinary kernel-checked declarations; this review does not turn a Python or native benchmark into mathematical evidence.
